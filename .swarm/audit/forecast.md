# forecast audit

Track: the demand-forecast input agents under `fetch/agents/` (weather, illness, WHO) plus the shared bridges in `fetch/shared/` and the smoke test in `fetch/scripts/`.

## Aligned with demo story

- **A real ingest entry point already exists, but it lives in `who_agent/fetcher.py`, not in a dedicated orchestrator.** `run_who_update(region)` (`fetch/agents/who_agent/fetcher.py:420`) is the closest thing to the north-star "Ingest Data" loop: it fetches WHO/JHU COVID data from disease.sh, *also* pulls live weather (Open-Meteo) and *also* reads the illness mock feed, merges all three into `forecast:{region}`, gathers inventory + vision + scenario snapshots from Redis, runs Claude reasoning (`reason_with_claude`, `:160`), and writes `reasoning:latest`. So WHO + weather + illness ARE driven from one call — the WHO agent is a de-facto aggregator of the other two feeds.
- **The dashboard "Ingest Data" button is wired.** `ui/app.py:450` exposes `POST /api/refresh_who`, which imports and calls `run_who_update(region=REGION)`. So the dashboard-button half of step 7 is real today (it just goes through the WHO fetcher). The UI also renders weather/illness/WHO/Claude stages (`ui/templates/index.html`).
- **Claude reasoning surfaces a structured proactive recommendation** — `{risk_level, priority_items, reasoning, recommended_action}` — exactly the "proactive reallocation/purchase recommendation" the story asks for, written to `reasoning:latest`. There is a rule-based `_fallback_reasoning` (`:291`) for no-API-key runs (fail-soft).
- **Forecast key shape matches the Redis track.** `who_agent/fetcher.py` and the weather/illness agents write `forecast:{region}` as `{"region","updated_at","items":{...}}`, identical to `redis/src/forecast.py:write_forecast`. `redis_io.upsert_forecast_items` (`fetch/shared/redis_io.py:33`) correctly merge-writes so weather and illness slices coexist. Key shape is sound.
- **Resilient ingestion.** Every external call (disease.sh, Open-Meteo, Redis, Claude) is wrapped in try/except with fallbacks — a single outage never kills the agent. Good demo hygiene.
- **A CDC stub feed exists** as raw data: `fetch/agents/illness_agent/mock_cdc_feed.json` (labeled "MOCK CDC/WHO ILINet feed").

## Redundant / dead / off-track

- **`mock_cdc_feed.json` is NOT wired to anything.** Confirmed by grep: no code references it. Both `illness_agent/agent.py` and `who_agent/fetcher.py:_read_illness_items` read `mock_illness_feed.json`. The CDC stub the story names is just an orphaned JSON file with content nearly identical to `mock_illness_feed.json` (only SF influenza differs: High vs Very High). There is no "CDC source" as a 4th feed — the story's "(+ a CDC stub)" is unbuilt.
- **`WeatherUpdate` / `IllnessUpdate` / `WhoUpdate` message models are dead.** All three `models.py` define `uagents.Model` message classes for agent-to-agent `ctx.send`, but every send site is a `# TODO` comment (`weather_agent/agent.py:123`, `illness_agent/agent.py:118`). The agents only write Redis; they never message an "intelligence agent." The models are aspirational, unused, and contradict the actual architecture (Redis is the bus, not uAgent messages). Candidates to cut or park.
- **The three uAgents are largely redundant given the WHO fetcher.** `weather_agent` and `illness_agent` each poll on an interval and write their slice, but `run_who_update` already fetches weather and reads the illness feed itself. For the demo's single-trigger ingest, the standalone weather/illness uAgents add little beyond a periodic background refresh; the actual ingest path is the WHO fetcher. Decide whether the standalone agents survive as background pollers or get folded into one orchestrator.
- **`WhoUpdate` field names don't match what's written.** `who_agent/models.py` calls them `covid_30d_cases` etc., but Redis fields are `who_covid_30d_cases`. Since the model is never sent, it's just dead-and-inconsistent.

## Buggy / untested / risky

- **FROZEN-CONTRACT VIOLATION (high severity, flag to lead): `fetch/shared/protocol.py` hand-defines the Fetch Payment Protocol messages.** Lines 64-87 declare `RequestPayment`, `CommitPayment`, `RejectPayment`, `CompletePayment`, `CancelPayment` as local `uagents.Model` subclasses. The frozen `agent-communication-layer/protocol.py:60` re-exports these *unchanged* from `uagents_core.contrib.protocols.payment` precisely because ASI:One matches by **schema digest** — a local redefinition is a different, incompatible protocol and would silently fail to route / fail card rendering. It also redefines the negotiation models (`SupplyRequest`, etc.) with **different fields** than the canonical ones (e.g. local `RequestPayment{transfer_ref,amount,payer,payee}` vs canonical `RequestPayment` carrying `Funds` + metadata; local `TransferProposal.from_/to` vs canonical `from_facility/to_facility`). This file is a parallel, drifted, pre-freeze copy of the contract. It is currently **unused by the forecast agents** (none of them import it — they only import `redis_io`), which limits live blast radius, but it MUST NOT be imported by any agent that talks to ASI:One/Agentverse, and arguably should be deleted to avoid someone importing it. **The canonical source is `agent-communication-layer/protocol.py`; `fetch/shared/protocol.py` should be removed or reduced to a re-export.**
- **`run_who_update` bypasses the merge helper and can clobber concurrent writes.** It uses raw `r.set(f"forecast:{region}", ...)` (`fetcher.py:468`) after a manual read-merge, instead of `redis_io.upsert_forecast_items`. If the weather or illness uAgent writes between the WHO read and write, that slice is lost (read-modify-write race, no atomicity/locking). Low-probability in a demo but a real correctness bug.
- **Illness key-shape inconsistency between agent and smoke test.** `illness_agent` and the WHO fetcher write the nested shape `items["illness"] = {influenza: "High", ...}`, and the UI reads `items.illness` (`index.html:475`). But `fetch/scripts/redis_smoke_test.py:27` writes FLAT keys `illness_influenza`, `illness_covid` and asserts on those. The smoke test passes in isolation but validates a schema **no agent actually produces** — it gives false confidence and would mask a regression. The harness and the agents disagree on the illness contract.
- **No crisis-type → at-risk-supply mapping anywhere (confirmed).** Grep for `crisis|at_risk|wildfire|research_crisis` in `fetch/` returns nothing. The north-star research step (infer crisis type → ranked at-risk supplies) does not exist in this track. Claude's `priority_items` output is the nearest analog but it reasons from disease/weather/illness numbers, not from a stated crisis prompt, and there is no `research_crisis` seam. This is the single biggest gap vs. the target story.
- **Hardcoded model id `claude-haiku-4-5-20251001`** appears in three places (`fetcher.py:257,245`, `agent.py:44`) with no central constant — drift risk if the model is bumped.
- **No tests for the WHO fetcher / Claude reasoning at all.** The only harness (`redis_smoke_test.py`) covers Redis round-trip with the wrong illness shape and never exercises `run_who_update`, `parse_covid_stats`, or the fallback.
- **uAgent ports/seeds use public dev fallbacks** (`weather_agent_dev_seed`, etc.) — fine for local, but the README itself notes Almanac registration errors without testnet tokens.

## Dependencies on other tracks

- **Redis track (`redis/src/`)** — hard dependency. `fetch/shared/redis_io.py` and `who_agent/fetcher.py` both `sys.path`-insert `redis/src` and import `redis_client`, `forecast`, `schema`. Key shapes (`forecast:{region}`, `hospital:{id}:inventory|surplus`, `vision:latest`, `scenario:heatstroke`, `reasoning:latest`) are all owned by the Redis track. Forecast write shape matches `redis/src/forecast.py` — good.
- **Hardware/vision track** — `fetcher.py:_get_vision_snapshot` reads `vision:latest` (written by `hardware/camera connection/sync_to_redis.py`). Soft dep (falls back to empty).
- **UI track (`ui/app.py`)** — consumes this track: `/api/refresh_who` imports `fetch.agents.who_agent.fetcher.run_who_update`; dashboard reads `forecast:{REGION}` and `reasoning:latest`. This is the live integration point of the ingest loop.
- **Agent-communication-layer (negotiation) track** — currently **no direct linkage.** The forecast track writes `reasoning:latest` / `forecast:{region}`, but nothing in the negotiation core reads them to trigger a proactive reallocation. The story's "surface proactive recommendation → negotiate" handoff is unbuilt; the dashboard's negotiation trigger comes from vision counts (`_vision_to_negotiation_params`), not from forecast reasoning. **The forecast→negotiation seam is the missing link.**
- **Naming drift:** `ui/app.py:472` references `STOCKPILE_REDIS=1`; forecast/negotiation code uses `BAYMAX_REDIS`. Cross-track env-var mismatch (per the known rebrand).

## Open questions for the lead

1. **Delete or re-export `fetch/shared/protocol.py`?** It's a drifted duplicate of the frozen contract (incl. Payment models) and a contract-violation landmine. It's unused by the forecast agents today — recommend removing it before someone imports it. Confirm nothing else depends on its (incompatible) shapes.
2. **Promote `who_agent/fetcher.py:run_who_update` to the official unified ingest orchestrator?** It already runs WHO + weather + illness + Claude from one call. Should the standalone weather/illness uAgents stay (as background pollers) or fold in, and should the chat-command half of the ingest trigger route to the same function?
3. **Is the CDC stub in scope?** `mock_cdc_feed.json` is unwired and ~identical to the illness feed. Wire it as a distinct 4th source, or cut it and let "illness" stand in?
4. **Where does the crisis-prompt research step live?** No crisis→at-risk-supply mapping exists in this track. Is the future `research_crisis` seam expected to feed the WHO fetcher (as a new input alongside disease/weather/illness), or to live in the negotiation/front-agent track? It needs an owner.
5. **Should forecast `reasoning:latest` drive negotiation?** Today the dashboard negotiates off vision counts, not off the Claude recommendation. Closing the forecast→negotiate loop is required for the proactive-reallocation story.
6. **Reconcile the illness schema** between the agents (nested `illness` map, what UI reads) and `redis_smoke_test.py` (flat `illness_*`). Which is canonical?
